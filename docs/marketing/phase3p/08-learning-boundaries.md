# Deliverable 8 — Learning Boundaries

**Phase 3P · 2026-09-09**

Each boundary states the risk, the mechanism that prevents it, where it is enforced, and how it is tested. "Enforced" means a hard check
in code, not guidance in a prompt.

| # | Risk | Mechanism | Enforced at | Test |
|---|---|---|---|---|
| 1 | **Overfitting one seller** (today 13/13 references are Lewis & Maese) | Seller-concentration rule: when > 60% of retrieved references share a seller, only `transferable_lessons` reach the brief; palette, typeface, ornament, band colour, wording and layout facets are stripped. The brief schema has no field that can carry a reference palette or typeface. `do_not_copy.seller_marks` is seeded from every seller in the library and the seller directory. | Retriever + brief validator + OCR/logo gate on the render | Retrieval with 100% L&M must produce a brief whose calibration block contains no colour hex, no font name, no ornament word, no L&M string (negative test on schema + string scan). |
| 2 | **Copying exact layouts repeatedly** | Layout signature distance: candidate ≥ τ_self from the last 5 accepted creatives of the same seller × class, and ≥ τ_ref from every library reference. Family rotation: the same family may not be used for more than 3 consecutive creatives of one seller × class unless only one family is eligible. | Calibration hard check + Director SELECT | Re-running the same brief 5× must yield 5 signatures pairwise ≥ τ_self; feeding a reference render as a candidate must HARD FAIL. |
| 3 | **Copying merchandise between events** | `lot.auction_id == brief.auction_id` asserted for every object; site photographs must carry a provenance row bound to the event; extracted-object assets are addressed by (auction_id, lot_id), never by a global pool. | Brief validator + compositor `obj()` assertion | A brief mixing two auction ids is rejected by schema validation and by the compositor. |
| 4 | **Inventing merchandise** | Unchanged: fidelity = CLEAN only; no generative fill, inpainting or object synthesis anywhere in the render path; the renderer composes existing alpha assets only. For `merchandise_mode = representative` (acquisition/brand), assets must be Advantage.Bid-owned or licensed, flagged "representative — not lots", and the campaign class must be acquisition or brand. | Extraction gate + schema (`fidelity: CLEAN`) + `merchandise_mode` cross-check | Representative mode in an auction class → schema rejection; a REVIEW object → rejection. |
| 5 | **Using unrelated seller branding** | Co-brand logo only from `cobrand.seller_logo_asset_id` in production; OCR + logo template match on the final render against the seller-mark blocklist minus the brief's own cobrand seller. | Render gate G12 | A render containing "LMAuctionCo" in a non-L&M brief HARD FAILS; the same string in an L&M co-branded brief passes. |
| 6 | **Turning every ad into a collage** | Family selection is rule-driven (Deliverable 6 §6): CATALOG_SCATTER rationed to 1 in 5 creatives per seller per quarter and only for themed/eclectic LAUNCH waves; scene families require ≥ 8 CLEAN objects across ≥ 4 families; few objects → LEFT_THIRD_WHITE at large scale; one object → SINGLE_LOT; acquisition/brand → non-collage; closing_soon → CLOSING_DAYS. | Family selector + Director SELECT audit | Family distribution report per month; a unit test that a 3-object catalogue cannot select CENTERED_WHITE or CATALOG_SCATTER. |
| 7 | **Assuming every campaign needs event photography** | ENVIRONMENTAL_PHOTO requires `merchandise_mode = photograph` with event-bound provenance; no stock photography source exists in the asset pipeline; online-only auctions cannot select the family. | Family selector + asset provenance | An online-only event with photographs attached still cannot select ENVIRONMENTAL_PHOTO unless `event_mode = on_site`. |
| 8 | **Mistaking Owner preference for a rigid template** | Principles are stored as ranges and qualities, never coordinates; the scorer rewards editorial irregularity (judge item 8) and penalises template-likeness; the anti-similarity check (2) makes literal reuse impossible; `title_position`, panel side, anchor choice and object selection are decided per event. Sidecar `transferable_lessons` are reviewed for coordinate-like language at index build (lint: no px, %, hex, font names). | Index lint + scorer | Lint fails on a sidecar containing a hex colour or a pixel value. |
| 9 | **Performance metrics overriding Owner brand standards** | Two-signal separation (Deliverable 7 Part C): performance can reorder candidates only after Owner gates pass; it cannot raise or lower `owner_weight`, add references, or change rules; a high performer is *proposed* to the Owner via CALIBRATION_REPORT. `owner_status` writes are permitted only from the four Owner sources in the schema's `status_history.source` enum. | Schema enum + service-level permission | A write to `owner_status` with source `performance` is rejected by schema; the learning service has no write path to the sidecars. |
| 10 | **Silent drift of the library** | Only Owner actions add, promote, demote or retire; the indexer never imports; every change is a `status_history` entry with a date and a source; `index.json` is rebuilt from sidecars only. Historical or mediocre creative is never bulk-added — the library's smallness is a feature. | Indexer | Indexer run with a foreign file in a non-category location reports it and does not index it. |
| 11 | **Reference images leaking into generation or publication** | Reference files are readable by the retriever/scorer service only; the compositor asset loader has no path to the library; publishing jobs enumerate assets from creative results, which cannot reference library hashes. | Service boundary + asset loader | An asset id equal to a library sha256 in a creative result fails validation. |
| 12 | **Class with no references treated as calibrated** | Empty class → confidence LOW, `owner_review_required = true`; nothing in that class can reach CREATIVE_READY without an Owner review record. | Retriever + obligation gate | An individual-seller creative cannot reach CREATIVE_READY without an owner review row. |

## Two clarifications the boundaries depend on

**Owner creative approval and campaign performance are different signals.** Approval says "this is us". Performance says "this worked
here, then". The system keeps both, learns from both, and lets neither impersonate the other.

**A reference is evidence of taste, not a target.** The scorer measures whether a new creative *behaves* like the approved ones; the
anti-similarity check guarantees it does not *look* like them.
