# 7 — Proving-Ground Plan (after VS Code implements 3P.2)

**Phase 3P.2 · 2026-09-11 · Five classes, multiple candidates each, no publishing. The test: can the engine transfer the Owner's preferences without reproducing any reference?**

## Common protocol

Every candidate: official logo composited at the logo stage (never rendered); light foundation; navy authority; red attention within
budget; copy profile named; physical audit and coverage fit passed; anti-similarity ≥ τ_ref from every reference including the Golds
(a Gold is never closer than any other reference); template-echo check (no ≥ 3 collaborator props together); capitalization by role;
claims through the A2 manifest; representative disclosure where applicable; A9 and destination gates asserted OFF; the packet shows
each candidate beside the class's references with signature distances and the structure chosen. Owner review through the 3P.1 feedback
record model; a GOOD with no required fixes seeds the library with an engine-made reference.

Each class produces candidates in **at least two structures** so the Owner's feedback widens the range rather than narrowing it.

## A. Individual Seller acquisition (Gold-calibrated)

Message: "Have Items to Sell?" / "Turn Your Items Into Cash." (approved campaign concept) with "You Can Do This." as the band script;
support line sentence-style, factual; CTA to the real create-auction destination. Candidates:

- **A1 FEED_FAST / LEFT_COPY room vignette** — 5 blocks, physically planned scene (anchor, side table beside, lamp behind, small objects
  on a surface; no collaborator prop checklist), logo at 40–50% width.
- **A2 ACQUISITION_RICH / CENTERED** — 9 structured blocks, centered headline, benefit row horizontal, merchandise below.
- **A3 ACQUISITION_RICH / person + props (landscape)** — a representative person disclosed as representative, no testimonial text, no
  logo on the laptop.
- **A4 Houston/NYC variant of A1** — adds the single availability line "Prefer us to run the sale? Ask about assisted service." with no
  price; the packet shows the claim manifest rejecting any percentage.

## B. Buyer growth (Gold-calibrated)

Slogan "The Smarter Way to Shop."; discovery language only; CTA wording bound to a real destination supplied by platform truth (if
no email-signup destination exists in production, the candidate says so and uses browse/discover instead — nothing is invented).

- **B1 FEED_FAST** — one two-beat headline, one support, one CTA, band; tabletop vignette with one red word in the headline.
- **B2 ACQUISITION_RICH with signup** — only if a real signup destination exists; the form is drawn from production truth.
- **B3 Environmental** — a bright interior photograph-style scene without a product screen; tests discovery without a laptop prop.
- **B4 Wordy control (NOT FOR PUBLICATION)** — deliberately at the 3P.1 GENERAL budget + two extra blocks, labelled, so the Owner can
  confirm the density line he drew.

## C. Professional Seller acquisition (approved references; variety required)

Slogan "The Smarter Way to Sell." as a separate element; capability/ease language ("Sell More", "From Inventory to Results.");
no software screens as hero.

- **C1 CENTERED** (REF-20 structure, different everything else) · **C2 LEFT_COPY serif** (REF-21 structure) · **C3 ASYMMETRIC** — the
  Owner named it valid and no reference shows it: headline low-left, merchandise high-right, CTA on the band · **C4 Environmental
  full-bleed** — a shop interior as ground with a quiet copy panel.

## D. Geographic event (a real Houston or NYC-area event from production)

Precondition: a real upcoming event in a strategic market. The Director walks the media ladder and records the trail. WHAT loudest
(event type), WHERE twice (eyebrow + environment or a seller photograph of the place), WHEN mandatory, WHY LOOK in one line.

- **D1 authentic-media banded** (the event's own photograph at tier ≤ 4) · **D2 LEFT_COPY** with the photograph right · **D3 landmark
  variant** only if the Director finds no ready authentic media (then the packet must show the ladder result that justified it) ·
  **D4 co-brand** if the event's seller is a Professional Seller (seller primary, Advantage.Bid mark at 60–90% weight).

## E. Notable lot (a real lot in a real event)

Precondition: a real event with a lot the Director selects by an explainable rule (highest estimate if enabled, else most-viewed, else
the seller's featured lot). Every fact from the lot/event record; the lot's own photograph as hero; light ground.

- **E1 fact-ladder LEFT_COPY** (REF-23 structure) · **E2 hero-dominant with minimal copy** (label, item, event/date, CTA, band) ·
  **E3 CATEGORY tie-in** — the notable lot plus two more lots from the same event as small secondaries, to test that the event, not the
  object, stays the destination · **E4 dark exception (NOT FOR PUBLICATION)** only if the lot is a lit/translucent/reflective object,
  so the Owner can confirm the exception rule; otherwise omitted.

## Regression using the new references

Before any candidate is generated: score REF-14…REF-23 with scorer v2 + the 3P.2 gates and record the baselines (expected: high on
hierarchy, light foundation, red budget and physical realism; `logo_source` FAIL on every one because their logos are rendered — this
is correct and demonstrates the gate; `template_echo` flagged on most — also correct). Then submit REF-15 as a candidate: G11 must
hard-fail (a reference is never a valid candidate). Then submit the six 2026-09-09 renders: the 3P.1 expected outcomes must hold.

## What the Owner sees

One page per class: the candidates first (structure named on each), the class's references beside them (Gold marked), then the numbers
— signature distances to every reference, copy profile and block count, red element count, logo box and feed-proxy measures,
physical-audit result, coverage, the media trail (D, E) and the claim manifest (A4, B2, E). His words go into the ledger through the
feedback record model.
